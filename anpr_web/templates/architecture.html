Architecture

One modular pipeline, two demonstration modes.

The access-decision prototype separates image capture, detection, OCR, normalization, matching, storage, and presentation.

Raspberry Pi live camera

The unchanged CLI reads a USB camera through OpenCV, runs periodic OCR, checks the local CSV registry, and draws an on-screen recommendation.

Flask web demo

The web mode validates temporary JPG or PNG frames and uses SQLite for fictional vehicles and retained visits. The server never opens the client camera.

Plate detection

OpenCV contour geometry locates plate-like rectangles. Uploads can use a conservative close-up fallback; the live detector keeps its original area limits.

OCR

The unchanged Raspberry Pi workflow uses EasyOCR with Japanese and English support. The free cloud demo sends only the detected crop through a provider-neutral HTTPS adapter to Google Cloud Vision TEXT_DETECTION. Tesseract remains an optional local fallback; every mode preserves exact matching.

Normalize and match

Whitespace is removed and text is uppercased consistently. Web authorization requires an exact normalized match to an active SQLite record; fuzzy matching is disabled.

Visit decision

After ALLOWED, the configured Entry or Exit action is applied transactionally. Open visits are unique per vehicle, history is never overwritten, and still images never imply direction.

Exit-summary email

The exit transaction commits before a uniquely keyed delivery record is attempted. Local or paid deployments can use SMTP; the free cloud demo uses a provider adapter over outbound HTTPS. Delivery failures cannot reopen a visit or change an access decision.

Parking overview

Occupancy counts open visits for current vehicles. A vehicle currently inside must exit before its registry record can be permanently deleted. Optional capacity produces availability and percentage displays only; reaching capacity does not block an access decision.

Administration records

Filtered history can be exported to an in-memory, formula-safe CSV. A paginated audit log records selected administrative actions without raw email addresses, secrets, images, or session data.

Browser camera registration

An authenticated admin browser sends occasional temporary frames for multi-sample detection and OCR. A corrected review form and explicit confirmation are required before shared registration validation saves anything.

Presentation

UTC timestamps are displayed in the configured local timezone. Searchable history, status metrics, and accessible saved light/dark themes remain presentation-only and do not control hardware.

Privacy behavior

Uploads use random temporary filenames and are removed after each request. Image and camera-assisted registration embeds review images in the response and does not retain original or cropped imagery. Public registry pages omit institutional IDs and private metadata. Optional visit-summary email requires explicit consent; only a masked destination and delivery outcome remain with retained history. Message bodies are never saved. Only fictional data belongs in this repository.

Limitations

This is an access-decision prototype, not a production ANPR system and not physical gate control. Accuracy and security are not independently calibrated. Durable hosted SQLite deployments need a single-instance persistent disk; this free portfolio deployment instead accepts temporary storage resets. In-memory login and camera sampling limits are process-local, and OCR or contour heuristics can fail. Camera access requires a secure browser context and user permission.
